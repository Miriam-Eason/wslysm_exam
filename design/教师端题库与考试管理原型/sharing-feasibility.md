# 系部共享题库 · 可行性讨论稿

## 当前实现

- `QuestionBank.subject` 是可选自由文本，创建或编辑题库时由教师手工输入；没有科目字典表。
- 题库列表只查询 `createdBy = 当前教师`。
- 题库详情、题目增删改、导入、模板、组卷等接口都按 `createdBy` 做所有权校验。
- `Teacher` 当前没有系部字段，系统内也没有系部实体。

## 共享后的权限边界

建议先明确四种能力，不能只做“能看见”：

| 能力 | 创建者 | 同系部教师 | 其他系部教师 |
| --- | --- | --- | --- |
| 查看题库与题目 | 是 | 待确认 | 否 |
| 用题目组卷 | 是 | 待确认 | 否 |
| 编辑题目/导入 | 是 | 默认否 | 否 |
| 删除、改名、转移归属 | 是 | 否 | 否 |

## “添加”的语义

需要区分两种完全不同的数据行为：

1. **引用/收藏**：题库仍归创建者；同系部教师把它加入自己的工作列表，用于搜索和组卷；内容更新保持同步；非创建者只读。
2. **复制**：在自己的账号下生成一份独立题库和独立题目；可自由编辑；内容不再同步，仓储与去重成本更高。

建议优先评估“引用 + 只读 + 按需复制”，不要默认复制整库。当前 Demo 中的“添加”暂时按本地复制演示，只用于表达入口，不预设最终后端语义。

## 可能需要的数据结构

- `Department`：系部主数据。
- `Teacher.departmentId`：教师归属系部，作为可见范围依据。
- 可选 `QuestionBank.visibility`：私有 / 本系部 / 全校；若学校规则固定为“本系部全部可见”，可先不加。
- 若“添加”是收藏/引用：`TeacherSavedBank(teacherId, bankId, createdAt)`。
- 若“添加”是复制：不需要关联表，但需要事务化复制题库与题目，并记录来源教师和来源题库。

## 代码影响面

仅在列表上增加系部筛选不够。凡是当前有 `createdBy === 当前用户` 的接口都要重新定义读权限和写权限，包括题库详情、题目列表/新建/编辑、导入预检/确认、模板下载、组卷、题目维度查询等。写入权限应继续只归创建者，除非另行定义协作编辑。

## 需要先确认

1. 同系部题库是自动全部可见，还是由创建者选择共享范围？
2. 共享是否跨系部？是否需要“校级公开”层？
3. “添加”是收藏引用还是复制副本？
4. 创建者调岗后，历史题库跟随个人还是保留在原系部？
5. 是否允许同系部教师编辑或导入题目？
6. 超管是否需要查看、停用或转移系部题库？
