# 考试管理筛选 · 数据说明

## 已可直接使用的数据

- 班级筛选：`ExamClass` 已建立考试与班级的多对多关系，可按班级查询。
- 状态筛选：可由 `deadline` 与 `deletedAt` 推导“进行中 / 已截止 / 已下架”，不需要新增字段。
- 创建时间、题量、作答人数：现有 `Exam.createdAt`、`ExamQuestion` 和 `Attempt` 已具备。

## 目前缺少的数据

`Exam` 没有科目字段，`ExamQuestion` 快照也没有保存来源题库或科目。现有组卷一次只使用一个题库，因此建议在创建考试时从所选题库复制一份 `subjectSnapshot`，避免后续题库改名或删除导致历史筛选失真。

可考虑的最小改动：

```text
Exam.subjectSnapshot String?
Exam.sourceBankId    Int?
```

`sourceBankId` 用于追溯，`subjectSnapshot` 用于稳定筛选。若后续支持跨题库组卷，则科目应改为“主科目 + 可选科目集合”的明确产品规则，不能只存一个字符串。

## 历史数据

已有 169 条考试没有明确科目来源。可尝试从考试名称和原题来源推断，但不应在没有人工核对的情况下自动写回。建议迁移时保留“未归类”，后续由教师补充。

## 列表实现边界

- 当前 Demo 在浏览器内筛选，用于验证信息架构。
- 正式实现应在服务端按 `classId`、`subjectSnapshot`、状态和搜索词组合查询，并分页返回。
- 班级计数会因一场考试关联多个班级而大于实际考试总数，这和 `ExamClass` 的多对多语义一致。
